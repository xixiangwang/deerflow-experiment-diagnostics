# 本地材料诊断入口

这是本项目的单用户演示页面，后端调用官方 DeerFlowClient。它与 server.py 的离线规则 API 是两个入口，也不是 DeerFlow 官方完整网页端。

## 启动

打开终端给出的链接。链接片段中的 access 是本服务的临时访问口令，不是模型 API Key；页面读取后会清除地址栏片段。也可打开 http://127.0.0.1:8890 后手动输入访问口令。口令不保存到浏览器本地存储。

按仓库 README 准备环境和索引后，在仓库根目录运行：

```bash
python outputs/experiment-diagnostics/launch.py console --host 127.0.0.1 --port 8890
```

页面支持日志、实验配置 JSON、环境 JSON、代码摘录和问题。点击“填入示例”只填写表单；点击“提交诊断”才发起真实模型调用并产生 API 用量。API Key 只在后端进程环境使用，页面无需填写。

结果包含观察证据、原因假设、修改建议、待执行验证计划、缺少的信息和工具轨迹，可下载 JSON 记录。结构检查通过只表示协议符合要求，不能证明模型语义正确。
协议版本 3 还会核对声明引用是否确实在本次检索结果中，并保存场景源码快照；引用来源匹配不代表语义正确。

## HTTP 接口

| 接口 | 作用 |
|---|---|
| GET /health | 只读健康状态，不调用模型 |
| POST /jobs | 提交材料 JSON，返回 202 和任务 id |
| GET /jobs/{id} | 查询排队、运行、完成或失败状态 |

任务提交和查询都要求 Authorization: Bearer 后接本服务访问口令。POST 顶层字段与 MATERIALS.md 相同，拒绝路径、命令、模型切换等未知字段；使用 application/json 和 Content-Length，最大 300,000 字节。

同时最多接受两个未完成任务，一个运行、一个等待。每个任务在独立 Python 进程调用既有材料诊断入口，避免官方配置缓存和工具全局绑定跨任务串用；任务超时为 600 秒。请求无法选择执行器、文件路径或模型。子进程不是安全沙箱，这条路径不提供代码执行工具。

## 数据与使用边界

提交前会做类型、长度检查和常见密钥脱敏，再写入 work/agent-jobs/{id}/materials.json。脱敏不是完备的秘密检测器，仍应自行移除私有信息。传输文件的哈希不代表原始上传字节哈希。

完整诊断记录在 reports/materials/ 下；下载内容是缩减后的结果与工具轨迹，不包含全部框架事件。页面只在 sessionStorage 保存最近的任务 id；刷新后输入访问口令，点击“恢复上次报告”即可读取，不会再次调用模型。

任务元数据原子写入 work/agent-jobs/{id}/job.json。服务重启时恢复最近最多 64 份记录；已完成任务可继续查询，排队或运行中的任务标为 interrupted，执行结果未知，不自动重试。损坏记录跳过，写入失败会显式提示；同一任务目录只有一个进程可写。重启前的工作进程可能已另存完整报告，须人工复核后再决定是否重提。

页面显示的完成表示任务已返回，模型协议失败会单独提示，验证状态始终为未执行。任务与材料目前不会自动清理，没有多用户隔离或磁盘配额。

默认只监听本机。非本机绑定要求显式 DIAG_ACCESS_TOKEN；当前没有 TLS、多用户隔离、账号管理或生产限流，不适合直接公开。服务器使用建议保留本机监听，经 SSH 端口转发访问；尚未在学校服务器实机验收。
